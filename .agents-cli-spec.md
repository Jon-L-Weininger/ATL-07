# Agent Spec: Resilient Food Equity & Surplus Broker (`a4i_food_broker`)

## Goal
Build an ADK Python agent (`a4i_food_broker`) that brokers perishable food surplus postings to community recipients in the Metro area before spoilage, combining BigQuery `VECTOR_SEARCH` (`gemini-embedding-2` via `AI.EMBED`), hard operational constraints (`cold_storage`, `max_pallets`, `pickup_window_hours`, `service_days`), USDA FoodKeeper shelf-life verification, and Census ACS `tract_demographics` equity metrics into an actionable **Match Brief** with backup and load-splitting options.

## Users & Interaction Mode
- **Primary users:** Surplus food dispatchers, food bank brokers, and grocery/restaurant logistics coordinators.
- **Channel:** Interactive chat / structured posting dispatch (`agents-cli run` / `adk web` locally first, then Cloud Run API/UI).
- **Latency budget:** < 15s end-to-end per surplus posting brief.

## Agent Pattern
- **Topology:** Single `LlmAgent` (`root_agent`, `gemini-2.5-flash`) for the Phase 1 core foundation, structured with modular toolsets so specialist sub-agents or workflow steps can plug in cleanly in later phases.
- **Reference recipe(s):**
  - `genmedia-for-commerce` — Reference pattern for integrating MCP toolsets alongside custom Python function tools and vector search.
  - `rag-vector-search` — Reference pattern for vector search tool wiring in ADK.
- **Agents:**

| Name | Class | Role | Model |
|---|---|---|---|
| `root_agent` (`food_surplus_broker`) | `LlmAgent` | Analyzes surplus postings (or `posting_id`s), checks USDA FoodKeeper shelf life, runs semantic + operational + equity matching via MCP Toolbox (`VECTOR_SEARCH`), computes clock/margin & pallet load-splitting via custom Python tools, and produces the 6-part Match Brief. | `gemini-2.5-flash` |

## State & Memory
- **Session state keys:**
  - `active_posting`: Current surplus item metadata (`item_category`, `item_description`, `pallets`, `needs_cold_storage`, `hours_remaining`, `pickup_window_hours`, `donor_org`, `donor_city`).
  - `candidate_matches`: Top ranked recipient rows returned from BigQuery `VECTOR_SEARCH` + equity context.
- **Persistence:** In-memory session service for prototype (`--prototype`); extensible to managed session storage on Cloud Run.

## Guardrails & Callbacks
- **Hard Operational Constraint Enforcement:** Never recommend a primary recipient whose `cold_storage` does not meet `needs_cold_storage`, whose `pickup_window_hours > hours_remaining`, or whose `profile_text` contradicts structured fields (e.g., `Harborview Neighbors Trust` / `Greenline Community Pantry` traps).
- **Load-Splitting:** When `posting.pallets > recipient.max_pallets`, explicitly compute a primary + backup split plan rather than over-allocating pallets to a single recipient.
- **Tie-Breaking by Equity:** When two recipients are operationally and semantically tied (e.g., `Cedar Street` vs. `Maple Street`), rank using nearest census tract `poverty_rate` and `food_insecurity_index`.

## Target & Infra
- **Deployment target:** Prototype locally first (`--prototype`), targeting `cloud_run` (`agents-cli scaffold enhance --target cloud_run`) for Phase 5 deployment.
- **GCP project / region:** `qwiklabs-gcp-04-e7160ff57547` / `us-central1` (BigQuery dataset `a4i_food` in `US`).
- **Required secrets:** Application Default Credentials (`gcloud auth application-default login`), `MCP_TOOLBOX_URL` (default `http://127.0.0.1:5000`).

## Success Criteria (feeds Phase 4 Eval)
1. Given any of the 10 `surplus_postings` (`SP-01` through `SP-10`) or a free-text surplus offer, the agent queries `a4i_food` via MCP Toolbox (`VECTOR_SEARCH` with `gemini-embedding-2`) and calls the custom Python logistics tool.
2. The agent avoids the planted data traps documented in `DATA_NOTES.md` (rejects `REC-501 Greenline Community Pantry` for food items, flags `REC-502 Harborview Neighbors Trust` cold-storage contradiction, resolves `REC-503` vs `REC-504` tie via tract equity, and bridges vocabulary mismatches `REC-505`–`REC-509`).
3. Output includes all 6 required Match Brief sections (Organization & address, Why them, Capacity vs. offer, Clock & shelf-life margin, Neighborhood equity context, Ready-to-send outreach message, plus Next 2 backup/split options).
